THE CHALLENGE

The Problem: Why Current LMS Platforms Fail

An invisible wall isolates over 15% of African learners from digital skills

1. Zero Sign Language

Standard video players offer no secondary video stream for sign language interpreters. Deaf learners are forced to rely on raw visual text without native linguistic interpretation.

2. Missing Amharic Subtitles

Commercial video hosts default to English automated speech recognition (ASR), which fails on accented Ethiopian English and offers 0 support for Ethiopic script (ፊደል).

3. Extreme Bandwidth Bloat

Mainstream streaming players push heavy 50MB–200MB video chunks with no audio fallback, instantly failing on Ethiopian 3G networks where data is expensive.

4. Assistive Traps for Blind Learners

Complex video overlays trap keyboard focus (tabindex > 0), lack audio descriptions for visual slides, and provide inaccessible documents that screen readers cannot interpret.

5. Disconnected Career Gateways

Even when students complete courses, application forms lack accommodation disclosure and have zero support for verifiable credentials, keeping qualified graduates locked out of employment.

UNDER THE HOOD

How Did We Build It: Technical Scaffolding

Strict typing, custom element lifecycle, and zero-dependency shadow architecture

1. Framework-Agnostic Web Components

Authored in TypeScript with strict: true, compiled to standard W3C Custom Elements using Vite & ESBuild.

Uses an open Shadow DOM to completely isolate player CSS tokens from the host platform's styles — guaranteed zero stylesheet collisions inside Savanna LMS.

2. Manifest-Driven Architecture (lesson.json)

Fully validated against our strict JSON Schema (lesson-manifest.schema.json).

Decouples content from presentation: media sources, qualities (1080p down to 240p), sign language tracks, audio descriptions, documents, offline packs, and skills are declared declaratively.

3. Monorepo Organization (npm Workspaces)

  • packages/media-kit: Core accessible player & job card components.
  • packages/lesson-schema: Canonical TypeScript types & JSON schemas.
  • apps/demo: Interactive Vite PWA demo application.
  • savanna: Live Savanna LMS host platform environment.
  • services/transcript-api: Python FastAPI microservice.

4. Dual-Mode Distribution Pipeline

Outputs both an ES Module (a11y-media-kit.es.js) for modern bundlers and a Universal UMD bundle (a11y-media-kit.umd.js) for legacy script tag embeds.

Tree-shakable and lightweight with zero external runtime dependencies.

ENGINEERING DEEP DIVE

Technical Breakthrough: Solving Sign Language Video Sync

Eliminating decoder seek-storms and black-screen flickering on secondary video streams

⚠️ The Browser Decoder Problem

In web browsers, playing two synchronized <video> elements causes severe black-screen flickering if synchronized naively with currentTime = X.

Standard video streams have 8-second keyframe intervals with B-frames. Attempting to seek flushes the browser hardware decoder, forcing it to decode hundreds of delta frames. The decoder enters an infinite seek loop and renders black.

💡 The Abugida Dual-Rate Micro-Sync Solution

1. Ultra-Tight GOP Encoding: Re-encoded lesson-esl.mp4 with a 0.5s keyframe interval (-g 15 at 30fps), zero B-frames (-bf 0), and +faststart. Random-access seek latency dropped from 300ms to <5ms.

2. Dynamic Rate Micro-Sync: If drift is between 250ms and 750ms, instead of executing a violent seek, the controller smoothly nudges the sign video speed to 1.08× or 0.92×.

Result: 100% smooth, continuous playback with ZERO dropped frames, ZERO black canvases, and ZERO flickering.
